# Release checks

This is a prepared source release, not confirmation of publication to a Git hosting service.

The release builder includes root source metadata, frontend, backend modules, migrations, prompts, synthetic fixtures, offline tests and three public scripts. It excludes personal work notes, live evidence, account profiles, database files, credentials, resumes, generated reports, old debug scripts and development environments.

Before publishing, run the complete offline test suite in a fresh virtual environment; then unpack the source archive into a new directory and verify startup in explicit demo mode with a newly created database. Demo should produce synthetic findings with evidence; a fresh real-mode startup must report unconfigured accounts/model honestly. No platform credentials may be required for the synthetic demo.

Real platform validation is a separate check using the maintainer's accounts. It must confirm source identity, completeness flags, quote offsets, task results and read-only boundaries. It does not establish unlimited access, unattended collection or availability under future platform changes. BOSS per-run detail budgets mean list counts can exceed full detail counts.

Scan the final source archive against actual private setting values without printing those values. Check forbidden file types, personal absolute paths, private data directories and obvious credential patterns. Store only scan counts and pass/fail receipts. MIT applies to this project's own code; dependencies and platform content retain their separate terms.

FinIntel currently targets a single user's local machine. Do not publish a hosted unauthenticated API or transfer the maintainer's `.local` directory as a starter dataset. Screenshots and videos are separate documentation assets; redact account information and preserve visible completeness and source limitations.

The interview release check covers the full BOSS result → exact frozen JD → selected X/XHS evidence → synthetic resume → matching → preparation → report path. It must reject forged, foreign-session and stale quotes, cover every selected material, retain source URLs without credential query parameters, and show stale-plan warnings after input changes. Browser checks use an isolated synthetic database; a separate configured-model check uses saved public sources and an explicitly fictional resume. Neither check may label fictional experience as the user's experience.
